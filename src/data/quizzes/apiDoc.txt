# Quiz Config API Documentation

This document defines the full quiz object contract used in this project, what each key means, and where it is consumed.

Primary type source: `src/types/quiz.ts`
Main runtime consumer: `src/pages/common/QuizPlayPage.tsx`

------------------------------------------------------------
1) Root Quiz Object
------------------------------------------------------------

Type: `Quiz`

Required keys:

- `id: string`
  - Unique quiz identifier.
  - Used by route `/quiz/:id` and quiz lookup from `quizzes` array.
  - Example: `"hp-short-quiz"`

- `title: string`
  - Display title shown in quiz play and results/share contexts.
  - Used in quiz page heading, share text, and share card quiz title link.

- `questions: QuizQuestion[]`
  - List of all questions for this quiz.
  - Current supported question type in this codebase: `multiple-choice`.

- `difficulty: "easy" | "medium" | "hard"` (`QuizDifficulty`)
  - Metadata used for listing and categorization.

- `category: string`
  - Category label (for example `"Harry Potter"`).

- `type: "multiple-choice"`
  - Quiz-level type (kept for backward compatibility).
  - Question-level `type` is still used for rendering and review metadata.

- `createdAt: string`
  - ISO timestamp.

- `updatedAt: string`
  - ISO timestamp.

Optional keys:

- `lifelineConfig?: QuizPluginsConfig`
  - Enables/configures timer and lifelines.

- `sounds?: QuizSoundsConfig`
  - Controls quiz sound effects.

- `resultsPageConfig?: QuizResultsPageConfig`
  - Results screen: emotional messaging bands and which social share buttons to show.
  - See section 5a.

- `shareCardConfig?: QuizShareCardConfig`
  - Shareable result card: headline, themes, pass threshold, challenge copy.
  - See section 5b.

------------------------------------------------------------
2) Question Object (Current: Multiple Choice)
------------------------------------------------------------

Type: `MultipleChoiceQuestion` (extends `BaseQuestion`)

Required keys:

- `id: string`
  - Unique question id.

- `question: string`
  - Question text shown in play and review.

- `hint: string`
  - Hint text used by lifeline/help systems.

- `type: "multiple-choice"`
  - Renderer discriminator.

- `options: QuizOption[]`
  - Exactly what is shown as answer options.

- `correctAnswer: number`
  - IMPORTANT: this is `option.id`, not option array index, in quiz data files.
  - In `QuizPlayPage` transform, this is mapped to index for engine use.

Optional keys:

- `image?: string`
  - Question media URL.

- `explanation?: string`
  - Post-question educational context.
  - Used in review page answer cards.

`QuizOption` shape:

- `id: number` (used by `correctAnswer`)
- `text: string`
- `image?: string`

------------------------------------------------------------
3) Lifeline / Plugin Config
------------------------------------------------------------

Type: `QuizPluginsConfig`

Timer:

- `timer?: { enabled: boolean; secondsPerQuestion: number }`
  - Enables per-question countdown.
  - Seconds are clamped by engine plugin to a safe range.

Lifelines (all optional):

- `maraudersMap?: LifelineConfig`
- `askDumbledore?: LifelineConfig`
- `felixFelicis?: LifelineConfig`
- `legilimency?: LifelineConfig`
- `revelio?: LifelineConfig`
- `freezeTime?: LifelineConfig`

`LifelineConfig` shape:

- `enabled: boolean`
- `maxUsagePerGame: number`
- `usageCount: number`

Note:
- `usageCount` in data is generally initialized to `0`.
- Runtime usage is tracked by quiz engine state during play.

------------------------------------------------------------
4) Sounds Config
------------------------------------------------------------

Type: `QuizSoundsConfig`

- `enabled: boolean` (master toggle)
- `correct?: boolean`
- `wrong?: boolean`
- `timerTickSubtle?: boolean`
- `timerPulseLow?: boolean`
- `timeout?: boolean`

Behavior:
- If `enabled` is false, no quiz sounds play.
- Optional flags default to enabled behavior unless explicitly false.

------------------------------------------------------------
5) Results & share configuration (on `Quiz`)
------------------------------------------------------------

5a) `resultsPageConfig?: QuizResultsPageConfig`

- `emotionalBandsConfig?: EmotionalBand[]`
  - Each item: `{ minPercent: number; message: string }`.
  - Drives the **top emotional hook** on the results page (`ResultHeader`).
  - Bands are evaluated **highest `minPercent` first**; first match wins.
  - Mapped in `QuizPlayPage` → `QuizResultsUiConfig.emotionalBands`.

- `socialShareConfig?: SocialShareConfig`
  - Keys: `whatsapp`, `twitter`, `facebook` (lowercase), each optional:
    - `enabled?: boolean` — show that share button on the results page.
    - `url?: string` — if set, that URL is opened instead of the default share URL builder.
  - Consumed in `src/quiz-results/pages/ShareCardPage.tsx` (dedicated share screen).
  - Behavior:
    - If **`resultsPageConfig` / `socialShareConfig` is omitted**: WhatsApp and Twitter buttons are shown (legacy default). Facebook is **not** shown.
    - **WhatsApp / Twitter**: if `socialShareConfig` is present, each is shown unless that entry has `enabled: false`.
    - **Facebook**: shown only when `socialShareConfig.facebook.enabled === true` (must be explicit).
    - Facebook “default” open uses `buildFacebookSharerUrl(shareUrl)` when `url` override is not set; requires `shareUrl` (current page URL from `QuizPlayPage`).

5b) `shareCardConfig?: QuizShareCardConfig`

- `headline?: string` — Share card title (default in UI: `"Certified Potterhead 🪄"`).
- `tagline?: string` — Subtext under headline; falls back to generated viral line if omitted.
- `challengeLine?: string` — Short line used in the card footer / challenge block; falls back to viral line if omitted.
- `themes?: ShareCardTheme[]` — Subset of `"light" | "dark" | "fun"` for the theme picker.
- `defaultTheme?: ShareCardTheme` — Initial theme.
- `passMark?: number` — Minimum **score percent** to show **Passed** on the share card progress block (default **60** in UI if omitted). Clamped 0–100 in `ShareCard`.

Mapped in `QuizPlayPage` → `QuizResultsUiConfig` (`shareCard.*`, `passMark`).

7) Data Flow (Where Keys Are Used)
------------------------------------------------------------

1. Quiz object is selected by route id in:
   - `src/pages/common/QuizPlayPage.tsx`

2. `questions` are transformed for engine:
   - Option-id based `correctAnswer` → option index.
   - `explanation`, `hint`, `image`, `type` are preserved for downstream use.

3. Engine executes gameplay:
   - Lifelines/timer from `lifelineConfig`
   - Sounds from `sounds`

4. On finish:
   - `answerHistory` + transformed questions → review answers map.
   - `resultsPageConfig.emotionalBandsConfig` → results emotional headline.
   - `resultsPageConfig.socialShareConfig` → which share buttons render and optional URL overrides.
   - `shareCardConfig` → share card copy, themes, and `passMark`.

5. Results module (`src/quiz-results/`):
   - `ResultsPage` — score summary + CTAs (Play again, Review answers, **Share card**).
   - `ShareCardPage` — full share flow (card preview, themes, download, social) when user taps **Share card** (same route, `QuizPlayPage` switches `finished` sub-view: `results` | `review` | `share`).
   - `ReviewPage` — per-question review.
   - `ShareCard` component — presentational card used inside `ShareCardPage`.

------------------------------------------------------------
9) Authoring Checklist
------------------------------------------------------------

- Ensure every question has a unique `id`.
- Ensure `correctAnswer` matches an existing `options[].id`.
- Keep `type` as `"multiple-choice"` for current renderer support.
- Add `explanation` if you want rich review cards.
- Put custom results messaging under `resultsPageConfig.emotionalBandsConfig`.
- Put share-card visuals and pass threshold under `shareCardConfig` (`passMark`, `headline`, `themes`, etc.).
- Use `resultsPageConfig.socialShareConfig` to toggle platforms or supply custom share URLs.
